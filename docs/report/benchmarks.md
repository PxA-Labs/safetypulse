# Text-generation benchmarks: IFEval and XQuAD en/hi/es (E2, Job 26; E1 frontier, Job 30)

Exploratory under `docs/prereg_amendments/2026-11-24-e1-e5-lexsi-feedback.md (cd72fc6)`. No pre-registered verdict or frozen threshold is touched. Generated by `tools/report_benchmarks.py` from `kaggle/executed/12_hf_jobs/files/job26_*.json` and `job30_*.json` (per-document scores, answer sha256 and answer length; no answer text exists in these files). Every summary score was recomputed from `per_doc` and asserted equal to the lm-eval summary in the same file. Bootstrap: B = 10000, numpy `default_rng(20261125)` (per question or prompt) and `default_rng(20261126)` (XQuAD by paragraph). Rebuild: `uv run python tools/report_benchmarks.py (or .venv/bin/python; needs Python >= 3.10 and numpy)`.

All runs: lm-evaluation-harness 0.4.13, greedy, chat template, no system instruction, bf16 compute, batch 32, L40S. Job 30 variants are compressed-tensors checkpoints that transformers decompresses on load, so these are quality numbers for the quantized weights, not speed or memory numbers.

### Are base answer hashes reproducible?

- Cross-job, identical batch composition (different benchmark): Job 29 re-generated the Job 25 English refusal-set completions in a later HF Job; judge flags agree base 119/119, u4 119/119, r5 119/119, r6 119/119, r72 119/119, u8 119/119 (`job29_*_summary.json` `per_model.*.en_vs_job25`). So same-input, same-batch generation did repeat across jobs on this stack at least once.
- Same model, same code, different batch composition: the 5-document smoke runs (`results/job26-test/*`, `results/job30-test/u4.json` in the private jobs repo at revision `a00444f39ca499338dae9bd62b3caed3f9d4c61b`; doc ids, answer sha256 and scored flags copied to `kaggle/executed/12_hf_jobs/files/job26_job30_smoke_hashes.json`, no text) vs the full runs, identical answer hashes: base: IFEval 1/5 (prompt-strict flag equal 5/5), XQuAD en/hi/es 5/4/5 of 5; alpaca_s1_125: IFEval 2/5 (prompt-strict flag equal 5/5), XQuAD en/hi/es 5/5/5 of 5; repaired: IFEval 2/5 (prompt-strict flag equal 4/5), XQuAD en/hi/es 4/5/5 of 5; u4: IFEval 1/5 (prompt-strict flag equal 4/5), XQuAD en/hi/es 4/4/5 of 5. IFEval answers (up to 1280 tokens) mostly change when the batch changes, so bf16 batched greedy generation here is not batch-invariant, though the strict flags of these few prompts mostly survive. Five documents per task is far too few to size the noise.
- Not testable from these files: whether a Job 26 base rerun with the same 541-prompt batches would give the same hashes. Job 22 found generation repeatable within a job but not always across jobs. The McNemar counts therefore include any run-to-run noise as well as the quantization effect; the size of that noise was not measured for IFEval.

## Empty XQuAD answers

XQuAD generation stops at the first newline (`until: ['\n']`), and an empty answer has answer_chars 0 and the sha256 of the empty string in every file. An answer is empty when generation stops before any visible text, either at a leading newline (`until: ['\n']`) or at an immediate end-of-turn/EOS token; the files hold no text or token ids, so the cause cannot be determined here.

| Model | Empty en / hi / es | hi: also empty in base | hi: new vs base | hi: base-empty not empty here |
|---|---|---|---|---|
| base | 1 / 41 / 25 | 41 | 0 | 0 |
| alpaca_s1_125 | 0 / 0 / 0 | 0 | 0 | 41 |
| repaired | 1 / 30 / 19 | 30 | 0 | 11 |
| u4 | 2 / 98 / 33 | 38 | 60 | 3 |
| r5 | 3 / 62 / 25 | 33 | 29 | 8 |
| r6 | 2 / 42 / 17 | 29 | 13 | 12 |
| r72 | 2 / 18 / 22 | 16 | 2 | 25 |
| u8 | 1 / 46 / 25 | 41 | 5 | 0 |

Hindi questions empty in all seven non-Alpaca models: 14; empty in at least one model: 112. u4's 98 Hindi empties contain 38 of base's 41 and add 60 new ones. Why 4-bit weights give more empty answers in Hindi (and Spanish, 33 vs base 25) than in English is **unexplained** by these data, and (run-log departure (f)) u4's Hindi score is not interpreted until it is explained. Since empty answers score 0, u4's Hindi F1 over non-empty answers (0.145, n = 402) is higher than base's (0.122, n = 459); neither all-answer nor non-empty F1 is a clean Hindi QA comparison.
