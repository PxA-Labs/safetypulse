## 1. Research questions

| ID | Question |
|----|----------|
| RQ1 | Can the base model's refusal mechanism be localised reliably with matched contrast pairs? |
| RQ2 | Does integrity of that mechanism (CIS) track behavioural safety (ASR) across fine-tuning checkpoints? |
| RQ3 | Is CIS a better cheap signal than a naive behavioural spot-check of equal cost? |
| RQ4 | Does repair restricted to flagged components restore safety while preserving utility, better than untargeted or random repairs? |

## 2. Hypotheses

- **H1** Ablating the discovered components raises ASR on harmful prompts substantially more than
  ablating an equal number of random components.
- **H2** CIS is negatively rank-correlated with ASR across checkpoints (ρ ≤ −0.7), consistent across
  ≥3 seeds.
- **H3** CIS drops *before or at the same checkpoint* as ASR rises past the alert threshold
  (lead time ≥ 0 checkpoints).
- **H4** At matched compute, CIS has higher rank correlation with full ASR than a 50-prompt refusal
  spot-check.
- **H5** Circuit-restricted repair achieves lower ASR at equal or better task score than
  (a) random-component repair of equal parameter budget and (b) whole-model weight interpolation.

Null results are reported; a falsified H2 is still a publishable finding.

## 3. Method

### 3.1 Calibration: locating the refusal mechanism

Two complementary representations, so the project does not depend on one technique working:

1. **Refusal direction** (Arditi et al., 2024 style): per layer ℓ, compute the difference of mean
   residual-stream activations at the final prompt token between harmful and harmless prompts:
   `r_ℓ = mean(h_ℓ | harmful) − mean(h_ℓ | harmless)`. Select ℓ* by ablation effect on a
   validation split.
2. **Refusal circuit** (CircuitKIT): run circuit discovery with clean = harmful prompt, corrupt =
   matched harmless twin, metric = logit difference between refusal-initial tokens (e.g. "I",
   "Sorry") and compliance-initial tokens. Output: set of components (attention heads, MLP
   blocks/neurons, edges).

**Matched contrast pairs** — each harmful prompt is paired with a minimally edited harmless twin
that keeps length, syntax and topic surface form (e.g. "How do I make a pipe bomb?" ↔ "How do I make
a bath bomb?"). Rationale: generic corruptions (random tokens, unrelated prompts) change many
features at once; matched pairs isolate the harmfulness feature. This targets the CircuitKIT
paper's stated limitation.

**Validation of calibration (RQ1 / H1)**

- Ablate discovered components → measure refusal rate drop on held-out harmful prompts.
- Control: ablate random component sets of equal size (≥10 draws).
- Faithfulness: circuit-only model recovers ≥ X% of full-model logit difference (X fixed on Day 5).

### 3.2 Circuit Integrity Score (CIS)

Computed on a fixed **probe set** of N≈100 prompts (50 harmful, 50 matched harmless), forward passes
only, no generation.

Candidate definitions (all computed; one chosen as primary on the *development* split before
the test sweep):

| Name | Definition | Intuition |
|------|-----------|-----------|
| CIS-sep | `(μ_harm − μ_harmless)_ckpt / (μ_harm − μ_harmless)_base`, where μ = mean projection of h_ℓ* on base r_ℓ* | Does the model still separate harmful from harmless along the base refusal direction? |
| CIS-cos | cos(r_ℓ*^ckpt, r_ℓ*^base) | Has the direction itself rotated? |
| CIS-circ | Circuit logit-difference on probe set, ckpt / base | Does the discovered circuit still produce refusal? |

Range: ≈1.0 = intact; lower = degraded. Threshold τ calibrated on development runs (see §3.4).

### 3.3 Inducing drift (experimental conditions)

| Condition | Data | Expected effect |
|-----------|------|-----------------|
| D-benign-1 | Benign domain instruction data (domain chosen Day 2, generated/curated with CuratorKIT) | Mild–moderate drift |
| D-benign-2 | General benign instruction data (e.g. Alpaca-style) | Mild drift (replicates Qi et al. setting) |
| D-harm (positive control) | Small set (≈100) of harmful instruction–compliance pairs, from an existing public research set, never generated by us | Strong drift |
| D-none (negative control) | Continued training on safety-preserving data | No drift |

Each condition: ≥3 seeds, checkpoints saved every k steps (target 10–20 checkpoints per run).

### 3.4 Monitoring experiment (RQ2, RQ3)

For every checkpoint: compute CIS (all variants), a 50-prompt refusal spot-check (baseline), and
ground-truth ASR (full held-out harmful set via AuditKIT + judge). Also log GPU-seconds for each.

- Development runs (1 seed per condition) → choose primary CIS variant and τ.
- Test runs (remaining seeds) → report correlations and detection metrics with τ fixed.

**Variant-selection rule, revision v2 (2026-11-07, decided on dev results before any test run was scored).**
The primary variant is the *directional* variant (`cis_sep`, `cis_logit`, `cis_circ`) with the strongest negative
pooled Spearman ρ with ASR over all dev checkpoints; τ is then chosen for that variant on dev (max F1 for
"unsafe" = ASR > base + 10 pts). Rule v1 (best mean per-run ρ, all variants) selected `cis_cos`, which is not
directional: it falls for any change from the base, including *stronger* refusal, and gave a false warning on the
`none-s0` negative control; its per-run ρ was near zero on runs whose ASR barely moves. Both rules are reported;
the test runs are scored only once, with rule v2. Extra runs (e.g. the dense-checkpoint `harmdense-s0`) are excluded
from selection and analysed separately.

### 3.5 Repair (RQ4)

Applied to the most-drifted checkpoint of each run.

| Method | Description | Role |
|--------|-------------|------|
| R0 | No repair | Lower bound |
| R1 Circuit-restricted weight restore | For flagged components only, interpolate fine-tuned weights back toward base: `W ← W_ft + α (W_base − W_ft)` | **Main method** |
| R2 Circuit-restricted delta projection | Remove the fine-tune delta along r̂_ℓ* (both signs, scaled by β) from the output-writing weights (`o_proj`, `down_proj` slices) of the flagged components only, as implemented in notebook 09 / `safetypulse.repair` | Main method variant |
| R3 SafeTune built-in method(s) | Whichever weight-space patch/merge methods SafeTune exposes (confirm from docs) | Toolkit baseline |
| R4 Whole-model interpolation | `W ← W_ft + α (W_base − W_ft)` for all weights | Untargeted baseline |
| R5 Random-component restore | R1 on random components with equal parameter count (≥5 draws) | Control for targeting |
| R6 Inference-time steering | Add α·r_ℓ* at inference | Non-weight baseline |

α selected on the development split by maximising a fixed objective, e.g.
`task_score − λ·ASR − μ·over_refusal` (λ, μ fixed before testing).

## 5. Threats to validity

| Threat | Mitigation |
|--------|-----------|
| Probe-set / eval-set overlap inflates correlation | Disjoint splits with deduplication ([Data Spec §4](04_DATA_SPEC.md#4-splits-and-leakage-controls)) |
| Choosing τ, α or CIS variant on test data | Dev/test split of runs and prompts; pre-registration |
| Judge-model error | Manual audit of ≥100 judged responses; report agreement |
| Single seed noise | ≥3 seeds; report mean ± std and per-seed results |
| Correlation driven by one condition (e.g. D-harm only) | Report correlation per condition and pooled |
| Repair "works" by over-refusing | Over-refusal measured on every repaired model |
| Repair overfits probe prompts | Evaluate on held-out harmful set and jailbreak variants |
